# ARCHITECTURE — Campus Placement Assistant

## 1. System Overview

The application is a local full-stack placement management system.

```text
                ┌──────────────────────┐
                │ React + Vite         │
                │ Frontend             │
                │ localhost:5173       │
                └──────────┬───────────┘
                           │
                           │ HTTP / JSON
                           v
                ┌──────────────────────┐
                │ FastAPI              │
                │ 127.0.0.1:8000      │
                └──────────┬───────────┘
                           │
              ┌────────────┼─────────────┐
              │            │             │
              v            v             v
         Students       Drives     Applications
              │            │             │
              └────────────┼─────────────┘
                           v
                    SQLAlchemy ORM
                           |
                           v
                    SQLite database
                    placement.db

Uploaded PDFs:

backend/uploads/jd/
          |
          v
FastAPI StaticFiles
          |
          v
/ uploads / jd / filename.pdf
```

## 3. React Context Layer

Current contexts:

```text
ApplicationContext.jsx
PlacementContext.jsx
ReminderContext.jsx
StudentContext.jsx
```

These provide application-wide state and behavior.

Conceptually:

```text
React App
   |
   +-- Student state
   |
   +-- Placement drive state
   |
   +-- Application state
   |
   +-- Reminder state
```

The project also contains API-backed functionality in `src/services/api.js`.

When debugging, determine whether a page gets data:

- directly from an API service,
- from a context,
- from local state,
- or from a combination.

Do not assume every displayed value comes from the backend.

## 6. main.py Responsibilities

`backend/main.py`:

1. Imports FastAPI.
2. Imports CORS middleware.
3. Imports `StaticFiles`.
4. Creates tables using SQLAlchemy metadata.
5. Creates FastAPI app.
6. Configures CORS.
7. Mounts `/uploads`.
8. Includes API routers.
9. Defines root endpoint.
10. Defines health endpoint.

The upload mount is required for PDF viewing.

---

## 7. Database Layer

```text
backend/database.py
```

This is the database configuration layer.

The application uses SQLAlchemy's `Base` and `engine`, with sessions supplied through:

```text
get_db
```

Routers receive database sessions using FastAPI dependency injection:

```python
db: Session = Depends(get_db)
```

## 11. Drive Architecture

Drive creation:

```text
CreateDrive.jsx
     ↓
createDrive()
     ↓
POST /api/drives/
     ↓
drives.py:create_drive()
     ↓
DriveCreate
     ↓
PlacementDrive
     ↓
SQLite
```

Drive retrieval:

```text
OpportunityDetails.jsx
     ↓
getDrive(id)
     ↓
GET /api/drives/{id}
     ↓
drives.py:get_drive()
     ↓
PlacementDrive
     ↓
DriveResponse
```

Drive update:

```text
EditDrive.jsx
     ↓
updateDrive()
     ↓
PATCH /api/drives/{id}
     ↓
drives.py:update_drive()
     ↓
PlacementDrive
```

Drive withdrawal:

```text
WithdrawnDrives/Admin drive controls
     ↓
withdrawDrive()
     ↓
PATCH /api/drives/{id}
     ↓
status = "Withdrawn"
```

The drive is not deleted.

## 12. JD Architecture

The JD is stored as a physical PDF plus database metadata.

```text
Original PDF
    |
    v
UploadFile
    |
    v
UUID generated
    |
    v
backend/uploads/jd/<uuid>.pdf
    |
    +--> jd = "/uploads/jd/<uuid>.pdf"
    |
    +--> jd_filename = original filename
    |
    v
placement.db
```

The original filename and stored filename are intentionally different.

This prevents filename collisions and preserves the human-readable filename.

## 13. Static PDF Serving

The backend mounts:

```text
/uploads
```

to:

```text
backend/uploads
```

Therefore:

```text
/uploads/jd/example.pdf
```

maps to:

```text
backend/uploads/jd/example.pdf
```

The frontend can use the backend origin plus that path.

## 15. Design Principle

Keep responsibilities separated:

```text
React pages
    = UI

services/api.js
    = HTTP communication

contexts
    = shared frontend state

FastAPI routers
    = request handling/business orchestration

schemas.py
    = validation/serialization

models.py
    = database representation

database.py
    = DB connection/session

uploads/
    = runtime file storage
```

When adding functionality, place code in the appropriate layer rather than putting everything into a page component or a router.
